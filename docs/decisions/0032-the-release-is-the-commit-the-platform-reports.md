# The tracker's release is the commit Coolify reports at runtime

- **Context.** No tracker event carried a release. `config/sentry.php` read only `SENTRY_RELEASE`, and the compose file set it from `${SOURCE_COMMIT:-}`, which arrived empty in every container since 2026-11-14. Coolify's source at tag v4.7.5, the host's version, shows why. Its compose parser creates an application variable for every `${...}` a service's `environment` names ([`parsers.php` lines 1847-1921](https://github.com/coollabsio/coolify/blob/v4.7.5/bootstrap/helpers/parsers.php#L1847-L1921)), so that line made an empty `SOURCE_COMMIT`; and a deployment adds Coolify's own `SOURCE_COMMIT`, the deployed commit or `unknown` without one, to the runtime `.env` only when the application has no variable of that name ([`ApplicationDeploymentJob.php` lines 4673-4683](https://github.com/coollabsio/coolify/blob/v4.7.5/app/Jobs/ApplicationDeploymentJob.php#L4673-L4683)). That `.env` reaches every service through the `env_file` the deployment adds ([lines 950-959](https://github.com/coollabsio/coolify/blob/v4.7.5/app/Jobs/ApplicationDeploymentJob.php#L950-L959)). The commit reaches a compose build only with the application setting `include_source_commit_in_build`, off by default ([migration `2025_11_26_124200`](https://github.com/coollabsio/coolify/blob/v4.7.5/database/migrations/2025_11_26_124200_add_build_cache_settings_to_application_settings.php#L20-L24)).
- **Decision.** Decided by the owner on 2026-11-16: the runtime route. `config/sentry.php` names the release after `SENTRY_RELEASE` when it is set, otherwise after `SOURCE_COMMIT` unless that is empty or one of Coolify's two stand-ins for a commit it could not name, `unknown` (no commit at all) or `HEAD` (kept when `git ls-remote` gave no commit, [lines 3748-3770](https://github.com/coollabsio/coolify/blob/v4.7.5/app/Jobs/ApplicationDeploymentJob.php#L3748-L3770)), either of which would put every such deployment in one release, and otherwise sends none. The compose file names neither variable, so the parser makes neither and a `SENTRY_RELEASE` set in Coolify is no longer overridden. `.env.example` lists `SOURCE_COMMIT`; `tests/Unit/ProductionContainerTest.php` pins the compose file's silence and each reading.
- **Consequence.** A deployment outside Coolify carries no release unless `SENTRY_RELEASE` is set. CI's `image` job is unchanged: the image holds no commit. The empty `SOURCE_COMMIT` the parser made, with its preview copy, must be deleted by hand once, because the parser never deletes a variable (runbook "Error tracker"); until then events still carry none. The other route, turning `include_source_commit_in_build` on and building the commit into the image, was not taken: it needs a build argument in the `Dockerfile` and the compose file, and Coolify keeps the setting off because a value that changes with every commit breaks the Docker build cache ([its comment](https://github.com/coollabsio/coolify/blob/v4.7.5/app/Jobs/ApplicationDeploymentJob.php#L4673-L4675)). Reversing decision 0015 now finds no `SENTRY_RELEASE` line in the compose file; it removes `SOURCE_COMMIT` from `.env.example` and the release cases from `ProductionContainerTest` instead.
- **To reverse.** Make `release` in `config/sentry.php` read `SENTRY_RELEASE` alone, drop `SOURCE_COMMIT` from `.env.example`, and invert the commit cases in `tests/Unit/ProductionContainerTest.php`. The compose line need not come back: it never carried the commit.
