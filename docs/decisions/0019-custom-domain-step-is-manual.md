# The custom-domain certificate step is manual; the application never calls Coolify

- **Context.** A verified custom domain needs a certificate, which Traefik requests once the host is added to the Coolify resource. The design's risk table names it: "Custom-domain TLS needs a manual Coolify step" (`docs/superpowers/specs/2026-09-10-cass-v2-design.md`, section 15).
- **Decision.** The owner's, with the design approved on 2026-09-10, whose mitigation for that risk is "Documented runbook; admin notification on verification; v2 may automate through the Coolify API." The platform admin adds the host to the Coolify resource by hand, from runbook "What you do when the email arrives", and the application never makes that call.
- **Consequence.** Automating it means a Coolify API token in the application's environment, and that token can rewrite the whole deployment (backlog, 2026-09-12; runbook "What you do when the email arrives").
- **To reverse.** The application would send the runbook's `PATCH` of the resource's `domains` itself, with a Coolify API token in its environment: from `App\Actions\Organizations\VerifyCustomDomain`, whose docblock says it does not talk to Coolify (`app/Actions/Organizations/VerifyCustomDomain.php:24`), and from `App\Actions\Organizations\ReleaseCustomDomain`, which says nothing tells Coolify (`app/Actions/Organizations/ReleaseCustomDomain.php:17`). No test pins the absence of the call; `tests/Feature/Organizer/CustomDomainMailTest.php` pins the admin's email that asks for the manual step.
