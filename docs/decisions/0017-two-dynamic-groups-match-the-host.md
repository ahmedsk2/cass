# Two dynamic groups match hosting-1: the off-host copy's and the certificate renewal's, with disjoint rights

- **Context.** The audit before the off-host copy was installed on 2026-11-14 (runbook "Installing the off-host copy") lists every dynamic group that matches hosting-1 and every statement that could reach it. Run before `cass-backup-host` was created, it found one group already matching the instance: `lb-cert-renewer`, made by the owner on 2026-08-08 so that the host renews the certificate of the OCI load balancer serving the `towardpcc.com` apex. Its policy, `lb-cert-renewal`, grants `read load-balancers` and `use load-balancers` where the permission is `LOAD_BALANCER_UPDATE`, and nothing in Object Storage. The runbook then asked that no dynamic group but `cass-backup-host` match the instance.
- **Decision.** Proposed by the session on 2026-11-14 and accepted by the owner with the merge of the record of that day, which adds this file (the owner approves that pull request): both groups stay. The instance principal holds the union of their rights, and the two are disjoint: `cass-backup-host-writes` gives it Object Storage, creating objects in `cass-offsite` and listing them, and `lb-cert-renewal` gives it the load balancer. The install went ahead on this exception, and the runbook's precondition now says what it protects: no other dynamic group that matches the instance may hold a right in Object Storage, and the audit lists every group that matches it, with its policies.
- **Consequence.** The canary of 21:45 UTC that day, run with both groups in force, proved the bucket's bounds: create and list allowed; read, delete, overwrite and the bucket listing refused. What the host could do to the load balancer before the install it still can, and no more; until the containers' metadata-service fence (B3) is in, that includes any container on the host. The audit at every third drill reads both groups' policies again.
- **What would change it.** A group that matches the instance gaining any right in Object Storage, or a new group matching it with one: the off-host copy's bounds would then no longer be its own policy's. Take that right or that match away, run the canary again, and write a new decision if the right has to stay.
- **To reverse.** Move the certificate renewal off hosting-1's instance principal, delete the policy `lb-cert-renewal` and the dynamic group `lb-cert-renewer`, and put the runbook's precondition back to "no dynamic group but `cass-backup-host` matching the instance", in "Installing the off-host copy" and in the "Off-host copies" table.
