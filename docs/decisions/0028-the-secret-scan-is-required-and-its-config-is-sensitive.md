# The secret scan is a required check, and its configuration files are sensitive

- **Context.** #79 added the `secret-scan` job (gitleaks, pinned by digest) to CI on 2026-11-15. It ran on every pull request since without a false finding, but a merge did not wait for it, and a pull request could silence it by adding a `.gitleaks.toml` or a `.gitleaksignore`, two files the rule book's sensitive-paths list did not name (backlog row "The secret scan can be silenced, and it is not a required check").
- **Decision.** The owner, on 2026-11-16, on the session's recommendation: `secret-scan` joined the required status checks of `main`'s branch protection at 03:53 UTC (`changes`, `test`, `scripts`, `browser`, `smoke`, `secret-scan`; `strict` stays off), set through the GitHub API in the owner's session, and `CLAUDE.md`'s sensitive-paths list names `.gitleaks.toml` and `.gitleaksignore`, so a pull request that adds either lists it with one line of why and the owner approves that line. `coverage` and `image` stay out of the required checks as before (decision 0011; `docs/HANDOVER.md`, CI row).
- **Consequence.** A pull request waits about fifteen seconds more for the scan, and a true finding blocks the merge until the secret is removed from every commit of the branch and rotated. The scan's two configuration files cannot appear quietly.
- **To reverse.** `gh api -X PATCH repos/ahmedsk2/cass/branches/main/protection/required_status_checks` with the contexts list without `secret-scan`, and delete the two names from `CLAUDE.md`'s list. No test pins either.
