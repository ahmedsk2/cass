# Identifiers that stay in the public documents, and the one that goes

- **Context.** The repository is public (decision 0011). The documents name the Coolify compose project id (`vag136azl5q2bv87qqzgblo1`, the runbook's container helper and the handover's Production row), a Cloudflare ruleset id (runbook "Cloudflare in front"), the owner's Windows user folder (the runbook's off-host key and restore drill sections, and four dated plans), and email addresses in the dated plans. Plan 12's review asked the owner which to keep.
- **Decision.** The owner, on 2026-11-16, on the session's recommendation. The compose project id stays: it is the string every host command matches containers by, it grants nothing, and the host accepts no connection from the internet except through Cloudflare. The Cloudflare ruleset id stays: it is meaningless without the account's API token. The Windows user folder goes: the runbook's commands use the placeholders `<tools>` and `<repo>` (the folders `docs/dev-setup.md` names), and the dated plans read `<user>` in its place. The email addresses were checked and all are fixtures (`example.org`, `.example`, `cass.test`, the platform's own sender and the commit attribution address), with three `gmail.com` fixtures in plan 4's test data; none is a person's, so none changes.
- **Consequence.** A reader of the public runbook cannot learn the owner's Windows account name; the runbook's drill commands need the two placeholders filled once per PC, which `docs/dev-setup.md` already asks for. `tools/docs/new-identifiers.sh` compares each file with its previous version, so a new identifier shows in review.
- **To reverse.** Nothing to undo for the two that stay; the path would return as a literal in the runbook, which no rule forbids and this file advises against.
