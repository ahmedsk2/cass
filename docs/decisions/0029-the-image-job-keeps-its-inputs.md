# The `image` job keeps its inputs: a Composer change does not build the image

- **Context.** CI's `image` job builds the arm64 production image under QEMU, 15 to 36 minutes, only on the Monday schedule, a manual dispatch, or a change to `Dockerfile`, `.dockerignore`, `docker/`, the compose files, `package.json`, `package-lock.json` or the workflow (`.github/workflows/ci.yml`, job `changes`). A `composer.lock`-only change, Dependabot's included, never builds the image, so an installation failure of a new dependency would show first in the deploy script's wait for a healthy container (backlog row "The `image` job does not run on a `composer.lock`-only change").
- **Decision.** The owner, on 2026-11-16, on the session's recommendation: the inputs stay as they are. The weekly scheduled build catches an installation failure within a week, and a deploy stopped by the script (`DEPLOY_FAILED`, exit 2 or 3) leaves the previous container running, so nothing is live and broken.
- **Consequence.** Every Composer pull request keeps its three-to-six-minute CI run; a dependency that installs under `composer install` on the runner but fails inside the image is found by the Monday run or at the next deploy, not on the pull request.
- **To reverse.** Add `composer.json` and `composer.lock` to the `changes` job's Docker inputs in `.github/workflows/ci.yml`. No test pins the list.
