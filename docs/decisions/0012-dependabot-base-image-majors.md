# Dependabot ignores the php and node base-image release lines

- **Context.** Dependabot's docker group (#29) offered `php:8.5-fpm-alpine` and `node:25-alpine`. A new base-image line changes what production runs, the suite is verified on PHP 8.4 only, and #29 did not build: OPcache is compiled into PHP 8.5, so `docker-php-ext-install opcache` fails. Closing a grouped pull request ignores nothing, so #29 would have come back every Monday.
- **Decision.** The owner decided on 2026-10-17 that Dependabot ignores the `php` and `node` majors and PHP's next minor line. In the `docker` block of `.github/dependabot.yml`, `php` ignores `version-update:semver-minor` and `version-update:semver-major`, because Dependabot reads `8.4-fpm-alpine` to `8.5-fpm-alpine` as a minor update, and `node` ignores `version-update:semver-major`. Such an upgrade is planned work: `php-version` and `node-version` in `.github/workflows/ci.yml` move together with the `Dockerfile`'s base images, and on PHP 8.5 `opcache` leaves `docker-php-ext-install`. The next target is PHP 8.5 with Node 26 LTS, skipping Node 25, which is end-of-life since 2026-06-01.
- **What still flows.** Digest updates of the current tags (`php:8.4-fpm-alpine`, `node:24-alpine`) and every `composer` image update: the base images' security fixes.
- **Alternatives.** Leaving the docker group open: rejected, because a red grouped pull request also holds back the digest updates inside it. Closing it each time: rejected, because closing a grouped pull request ignores nothing and it returns every Monday.
- **Consequence.** Nothing proposes a new PHP or Node line any more; the backlog entry under "Dependencies" in `docs/superpowers/plans/backlog.md` is the reminder. Node 24 leaves active LTS on 2026-10-20 and is supported until 2028-04-30.
- **To reverse.** Delete the `php` and `node` entries under the `docker` block's `ignore:` in `.github/dependabot.yml`; no test pins them.
